## Executive Summary

1. **Core Thesis Holds Conceptually, Undermined by Stale & Confounded Claims `[MEASURED]`:** Compact textual line maps (`REV:N`, `<=60` capped elements, `filter_query`, on-demand `blind_gap` image crops) dramatically cut UI context tokens vs screenshots on simple/medium UIs (`54.5–524.5` estimated tokens vs `1,229` Anthropic heuristic on `form.html` and live GitHub Trending `[MEASURED]`), and the production merges (`AutoSetFocus=0` + `DirectCdpClient` + `verify_fresh`) delivered real speedups (`Api.execute_action()` browser `p50 = 17.38 ms` on corpus `[MEASURED]`). However, multiple headline benchmarks and architecture docs contain stale artifacts, confounded baselines, circular ground truth, unexecuted VLM claims, and active test/discovery bugs.
2. **Reproduced Test Failures (`2026-11-26` Run) `[MEASURED]`:**
   - Full `pytest tests -v -rs --tb=short` exited **`1`**: **`43 passed, 1 failed, 8 warnings`** in `68.35s` (`tests/test_mcp_server.py::test_mcp_windows_desktop_notepad_flow` failed at line `464`: `AssertionError: Notepad window failed to appear`).
   - Standalone `python tests/test_e2e.py` exited **`1`**: **`7/8 passed`** (`test_windows_desktop_end_to_end` failed: `notepad window not found`) and **mutated tracked `results/e2e/e2e_results.json`** on disk.
3. **Top Genuine Code/Engine Defects Found `[MEASURED]`:**
   - **Browser `$O(N^2)$` Occlusion Wall (`P-01`):** `BrowserSession.discover()` runs `is_occluded_in_snap()` across *all* layout boxes (`5,057` nodes on a `2,500`-cell DOM, `~12.9M` theoretical pairs), burning `295–2,689 ms` of local Python CPU (`41%–78%` of total discovery wall time) on non-interactive `<td>`/`#text` elements.
   - **Silent Cross-Origin OOPIF Drop & Role Degradation (`P-02`):** `Accessibility.getFullAXTree` is queried on the main page target only (`Target.getTargets` never attaches to OOPIFs). On `DualOriginCorpusServer`, `Cross Origin Save` (`<button>`) has **`0%` recall** and `OOPIF Email` (`<input>`) degrades to `role="clickable"` (`recall=0.9412`, `prec=0.80` for Control CDP itself).
   - **Missing `searchbox` Role (`P-03`) & Corpus FPs (`P-04`):** `<input type="search">` lacks `"searchbox"` in `ROLES`/`INTERACTIVE`, downgrading search fields to `role="clickable"` (`actions="click"`) across Wikipedia and Python.org; `_prune_nested_clickables` misses child `#text` inside `div[onclick]` (`Custom Div Action`) and bare `<label for>`.
   - **Duplicate Pre-Action Probe (`P-05`) & Per-Action `os.fsync` Tax (`P-06`):** `execute_action()` calls `DOM.resolveNode` + `_NODE_PROBE_JS` twice (`verify_fresh()` + `perform()`, wasting `5.25 ms` `p50`), and `TaskState.record_action()` executes synchronous Win32 `FlushFileBuffers` (`4.53 ms` `p50`), which `Exp 8` (`bench_action_freshness.py`) accidentally omitted from the candidate arm (`9.543 ms` reported vs `17.38–23.73 ms` actual).
   - **Win11 Store Notepad & UWP Capture Gaps (`P-09`, `P-10`, `P-11`):** `AppExecutionAlias` spawns child `Notepad.exe` under `WindowsApps`; `proc.terminate()` leaks child PIDs, single-instance tab reuse breaks `after - before` HWND diffs (`15s` timeout), `blind_gap.capture_desktop_region()` tries `ImageGrab` before `DWMWA_CLOAKED`/foreground checks (capturing IDE over Settings), and top-level `ctypes.WinDLL("user32")` imports break non-Windows importability.

### Constraints & What Could Not Be Reproduced `[MEASURED]`
1. **Desktop Isolation in Terminal (`ThreadDesktop: exebox-RQDBU4AJVW57BQL5KR4LG4DVVG` vs `InputDesktop: Default`):** `run_command` shells execute inside an ephemeral `exebox-*` Win32 desktop (`EnumWindows total=0` initially `[MEASURED]`, blocking visibility of user-desktop File Explorer, Obsidian/Electron, Taskbar `Shell_TrayWnd`, `GetCursorInfo`, and user-desktop `PrintWindow` occlusion checks). Only apps spawned *within the same shell desktop* (e.g., Store `Notepad.exe` on clean first launch before instance contention) are visible to `run_command` scripts. **Needed to reproduce `Exps 1–5`, `H2`, and Explorer/Settings `PrintWindow`:** run interactively inside an unlocked `WinSta0\Default` user desktop session.
2. **Missing External Software & API Keys:** LibreOffice Writer is not installed (`{"error": "LibreOffice not installed"}` in `h2_gate0.json` `[MEASURED]`). No `OPENAI_API_KEY`, `GEMINI_API_KEY`, or running Ollama model was configured for `bench_agent_20tasks.py`, so live VLM task-success and real API token usage could not be measured here.
3. **Tokenizer Binary Check:** `tiktoken` was not installed in Python `3.12.10` (`ModuleNotFoundError`), so BPE subword inflation on Arabic/URLs was verified structurally via UTF-8 byte/char lengths `[MEASURED]` and external tokenizer patch rules `[DOCUMENTED]` rather than local `tiktoken` counts.

### `P-01` — Browser $O(N^2)$ Python Occlusion Loop on Dense DOMs (`/large`, SPAs)
- **Symptom & Evidence:** On synthetic `2,500`-cell `<table>` (`5,057` layout nodes, `2,556` painted boxes, `7,558` AX nodes), `BrowserSession.discover()` took `715.8 ms` `[MEASURED]` (matching `707.1 ms` on live `/large` in `step 2258` `[REPORTED]`).
- **M3 Root Cause (Stage Breakdown):**
  - `DOMSnapshot.captureSnapshot` (CDP WS transport + Blink serialization): `95.4–143.8 ms` `[MEASURED]`
  - `Accessibility.getFullAXTree` (CDP WS transport + AXTree): `288.0–344.2 ms` `[MEASURED]`
  - Local Python unpacking (`bounds`/`styles`): `37.7–39.6 ms` `[MEASURED]`
  - Local Python `_collect_css_hover_triggers` (`0` hits): `11.2 ms` `[MEASURED]`
  - **Dominant local stage — `is_occluded_in_snap()`**: Runs `for ni, b in boxes.items()` (`5,057` nodes — *before* interactive filtering!) against `lay_items` (`2,556` items), costing **`~295 ms` (`41%` of `discover()`)** in `discover()` with early break, and **`2,689.3 ms` (`12,925,692` naive pair iterations)** when few nodes are occluded `[MEASURED]`. `5,056` of those `5,057` checked nodes are non-interactive `<td>`/`#text`/`<tr>` nodes discarded later anyway.
- **M4 External Research:**
  - CDP `DOMSnapshot.captureSnapshot` `includePaintOrder: true` returns layout bounds and paint orders in one call ([https://github.com/chromedp/cdproto/blob/master/domsnapshot/domsnapshot.go](https://github.com/chromedp/cdproto/blob/master/domsnapshot/domsnapshot.go) — canonical Go CDP schema mirror generated from Chromium PDL `[DOCUMENTED]`), while Chromium's DevTools team tracks AXTree serialization overhead as a known bottleneck on large DOMs ([https://github.com/ChromeDevTools/chrome-devtools-mcp/issues/363](https://github.com/ChromeDevTools/chrome-devtools-mcp/issues/363) — official ChromeDevTools MCP issue tracker `[DOCUMENTED]`). No official Chromium doc recommends computing pairwise $O(N^2)$ paint-order occlusion in Python; comparable OSS tools either skip full static-node pairwise occlusion (`playwright-mcp` builds AX text snapshots directly: [https://playwright.dev/mcp/introduction](https://playwright.dev/mcp/introduction) — Playwright official docs `[DOCUMENTED]`) or evaluate visibility/hit-testing in-page.
- **M5 Solutions & Scoring:**
  - **Ideal Solution:** Defer `is_occluded_in_snap()` until *after* candidate filtering (`clicked | cursor:pointer | ROLES`), reducing `N` from `~5,057` layout nodes to `~1–160` interactive candidates, *and* skip offscreen boxes + sort/sweep-line `lay_items` by `(y0, y1)` or bounding grid (`40 ms` -> `<3 ms`).
    - *Expected Gain:* Eliminates `290–2,600 ms` local CPU (`>95%` reduction in Python CPU `[INFERRED]`) with zero accuracy loss. *Cost/Risk:* ~30 LOC in `browser_cdp.py`, low risk if `occluded_bids` is computed identically on interactive `ni` candidates using viewport-clipped `lay_items` (skipping full-viewport containers already excluded or handling ancestor exemptions). *Measurement:* Benchmark 2,500-cell DOM + `corpus_main` modal test.
  - **Cheaper Alternative:** Move the `is_occluded_in_snap()` filter after `AXTree` merge so it checks only keys in `elements` (`O(|elements| * |lay_items|)` instead of `O(|boxes| * |lay_items|)` — a 10-line refactor).
  - **Graceful Fallback:** Keep `elementFromPoint` in `verify_fresh()`/`perform()` as the final occlusion guard if fast discovery misses complex stacking contexts.
  - **Pre-Set Test Plan:** `discover()` on `2,500`-cell DOM (`5,057` boxes) completes local Python processing `< 30 ms` and total `discover()` `< 450 ms`, while `corpus_main` `modal_occluded` preserves exact occluded exclusions (`recall`/`precision` parity).
  - **Q/A/S:** **Quality:** Gain `[INFERRED]` | **Accuracy:** Neutral (Exact equivalence `[INFERRED]`) | **Speed:** Major Gain (`-290 ms+` `[MEASURED]` bottleneck removed). *Tradeoffs:* None.
  - **Over-Engineering Check:** Replacing Python parsing with Cython/Rust is unnecessary over-engineering; filtering *after* interactive selection + viewport-pruned `lay_items` is trivial and solves the dominant Python wall.

### `P-02` — Cross-Origin OOPIF Discovery Failure & Role Downgrade
- **Symptom & Evidence:** On `DualOriginCorpusServer` (`corpus_main.html` + cross-origin `corpus_iframe.html`), `Control CDP` scores `recall=0.9412, prec=0.80` (`[MEASURED]` + `exp6_7_9_browser.json`). `Cross Origin Save` (`<button>`) is completely omitted; `OOPIF Email` (`<input>`) appears *only* by accident as `role="clickable"` (`actions="click"`, missing `"type"` `[MEASURED]`).
- **M3 Root Cause:** `Target.getTargets()` returns only the main page target `[('page', ..., 'corpus_main.html')]` `[MEASURED]`. `DOMSnapshot.captureSnapshot` returns `documents=2` (cross-process snapshot flattened inside Chromium), where Blink marks `<input>` in `isClickable` (so it appears sans AX role as `clickable`) while plain `<button>` without `cursor:pointer` has neither `isClickable` nor `cursor:pointer`. Meanwhile `Accessibility.getFullAXTree` inspects **only the main renderer process** (`Iframe` node `126`, `childIds: []` `[MEASURED]`), never piercing into OOPIF renderer processes.
- **M4 External Research:**
  - Chromium Site Isolation hosts cross-origin frames in separate renderer processes (OOPIFs). Retrieving OOPIF AX trees via CDP requires `Target.setAutoAttach({autoAttach: true, waitForDebuggerOnStart: false, flatten: true})` and issuing `Accessibility.getFullAXTree` with each OOPIF's `sessionId` ([https://chromedevtools.github.io/devtools-protocol/](https://chromedevtools.github.io/devtools-protocol/) — official CDP specification `[DOCUMENTED]`; Chromium issue [https://issues.chromium.org/40639208](https://issues.chromium.org/40639208) — official Chromium tracker `[DOCUMENTED]`).
  - **Alternative documented conflict:** `DOMSnapshot.captureSnapshot` *does* traverse child frame documents (`docs[1..]`) when flattened at browser level, whereas `Accessibility.getFullAXTree` does not aggregate across OOPIF targets on a single page session (`frameId` param only scopes frames within the same renderer target `[DOCUMENTED]`). Meanwhile, `agent_tasks.py::b09_cross_origin_oopif` passed oracle validation only because the test iframe button likely triggered `isClickable` (`onclick` / cursor), masking the bug on semantic native buttons.
- **M5 Solutions & Scoring:**
  - **Ideal Solution:** Enable `Target.setAutoAttach(..., flatten=True)` on `DirectCdpClient` (routing `{sessionId}` per OOPIF iframe target) and fan out `Accessibility.getFullAXTree` across active `iframe` targets in parallel with main `DOMSnapshot`, merging via `backendDOMNodeId` + iframe `doc_offsets`.
    - *Expected Gain:* Lifts OOPIF recall (`0% -> 100%` for buttons) and restores `textbox` role/type action on `OOPIF Email` (`[INFERRED]`). *Cost/Risk:* Requires multiplexing `sessionId` responses in `DirectCdpClient` (~80 LOC) + handling mid-discovery OOPIF detach (`~2–6 ms` extra per OOPIF target). *Measurement:* `DualOriginCorpusServer` OOPIF recall `== 1.0`, role accuracy `== 1.0`.
  - **Cheaper Alternative:** Inside `DOMSnapshot` (`docs[d_idx]` for `d_idx > 0`), infer basic HTML tag roles (`button`, `a`, `input[type]`, `select`, `textarea`) from `nodeName` + `attributes` when `d_idx > 0` and `bid` is missing from `AXTree` — ~20 LOC, zero extra CDP round trips (`is_clickable`/tag fallback)! *(Tradeoff: loses computed `aria-labelledby` semantics inside OOPIFs, though native `button`/`input` tags + `aria-label`/`placeholder`/`child_text` recover >90% of OOPIF controls `[INFERRED]`.)*
  - **Graceful Fallback:** Retain `Playwright` `page.frames` fallback only when `DirectCdpClient` reports `Iframe` nodes missing AX coverage.
  - **Pre-Set Test Plan:** Tighten `test_benchmarks_study.py::test_corpus_dual_origin_and_js_vs_control_coverage` from `>= 0.85` to `assert "cross_origin_iframe" not in ctrl_acc["failure_breakdown"]` and `OOPIF Email` `role == "textbox"`.
  - **Q/A/S:** **Quality:** Major Gain | **Accuracy:** Major Gain (`0% -> 100%` OOPIF `<button>` `[INFERRED]`) | **Speed:** Minor Loss (`+2–8 ms` on pages with OOPIFs for full CDP attach; `0 ms` with tag-fallback).
  - **Over-Engineering Check:** If 95% of real-world OOPIFs are payment/login widgets (`Stripe`, `reCAPTCHA` where bots shouldn't operate) or simple embeds, the **Cheaper Alternative** (`DOMSnapshot` tag fallback across `docs[1..]`) gives immediate `<button>`/`<input>` OOPIF coverage at zero latency/complexity cost; full `flatten: true` session routing is justified when supporting complex multi-frame enterprise SaaS/Stripe-style embedded forms.

- **M5 Solutions & Scoring:**
  - **Ideal Solution:** Add `"searchbox"` (normalized to `"searchbox"` with `"click,type"` in `ACTIONS` and included in `INTERACTIVE` + `inspect_element` `read_value()`, or mapped to `"textbox"` for uniform UIA/CDP schema parity, alongside `"spinbutton"`/`"combobox"`).

  - **Pre-Set Test Plan:** Add `input[type="search"]` to `test_engine_audit.py` asserting `"type"` in line-map actions and `inspect_element` returns value `[REDACTED if secret else text]`.

### `P-04` — Corpus & SPA Discovery False Positives (`label`, `div[onclick]` child, Offscreen & Scroll-Clipped Controls)
- **Symptom & Evidence:** On `DualOriginCorpusServer`, `discover()` emits `4` false positives (`prec=0.80` `[MEASURED]`): (1) `('clickable', 'Search SKU', ...)` from `<label for="query_input">`, (2) duplicate `('clickable', 'Custom Div Action', ...)` (`cursor:pointer` child `#text` inside `isClickable` div), (3) `Below Fold Action` at `y=1104.0` (`vh=720`), (4) `Scroll Inner Hidden` (`y=336` clipped inside `90 px` `.scroll-box` `overflow-y:auto`).
- **M3 Root Cause:**
  1. Blink marks `<label for=...>` as `isClickable=True`, duplicating the associated `<input>`.
  2. `_prune_nested_clickables()` ([browser_cdp.py:590](../../src/computer_use_lite/browser_cdp.py#L590)) only collapses children under `ax_parent_roles = {"button","link","menuitem","tab","checkbox","radio","switch"}` — excluding `"clickable"` parents (`<div id="custom_div">`).
  3. `BrowserSession.discover()` returns *all* non-occluded elements regardless of viewport bounds (`resolver.merge` filters `visible()` afterward in `Api`, *after* `BrowserSession` paid processing cost; furthermore, `DOMSnapshot` occlusion checks do not walk ancestor `overflow:hidden`/`auto` scroll-container clip rects!).
- **M4 External Research:** MDN & CSS Overflow spec confirm elements scrolled out of an `overflow: hidden|auto` ancestor keep valid layout bounds (`getBoundingClientRect` / `DOMSnapshot` rects) while being clipped from `document.elementFromPoint` hit-testing ([https://issues.chromium.org/40639208](https://issues.chromium.org/40639208); CDP `DOMSnapshot` bounds do not pre-clip to scroll ancestors `[DOCUMENTED]`). Comparable agents (`Stagehand` [https://www.stagehand.dev/](https://www.stagehand.dev/) `[DOCUMENTED]`) filter un-interactive `<label>` proxies and clip to visible scroll containers.
- **M5 Solutions & Scoring:**
  - **Ideal Solution:** (a) Skip `tag == "label"` when `for` points to a captured control (or keep only standalone custom labels); (b) include `"clickable"` non-native parents with matching text/box overlap inside `_prune_nested_clickables()`; (c) record ancestor `overflow != visible` boxes during the single `DOMSnapshot` doc pass and skip descendants whose midpoints fall outside their scroll-ancestor clip rect.
    - *Expected Gain:* Eliminates `4/4` corpus FPs (`prec 0.80 -> 1.00` `[INFERRED]`) and prevents agents from wasting cap slots or clicking invisible scroll-clipped controls. *Cost/Risk:* ~25 LOC; risk of dropping `<label>` toggles if native `<input>` is CSS `sr-only` (`0x0` hidden) — guard by keeping `<label>` ONLY if no matching `for=` input exists in `elements`. *Measurement:* `corpus_main` `precision >= 0.95`, test custom hidden-input `<label>` toggle.
  - **Cheaper Alternative:** Just add `"clickable"` (same-name/contained text child) to `_prune_nested_clickables()` and skip `visible(b)` elements outside viewport in `discover()` (saves ~5 LOC; skips `Scroll Inner Hidden` check until `perform()`).
  - **Graceful Fallback:** `verify_fresh()`'s `elementFromPoint` already blocks `Scroll Inner Hidden` at action time with `StaleElementError` (costing 1 failed turn).
  - **Pre-Set Test Plan:** `corpus_main` precision raises `0.80 -> >=0.95` while retaining custom `sr-only` checkbox `<label>` support.
  - **Q/A/S:** **Quality:** Gain | **Accuracy:** Gain (`+0.15–0.20` prec `[INFERRED]`) | **Speed:** Slight Gain (fewer elements merged/emitted).
  - **Over-Engineering Check:** Computing full CSS clip-path transforms is overkill; simple `overflow-x/y` parent rect intersection (`hidden`/`auto`/`scroll`) + `<label for>` + `"clickable"` dedupe is lightweight and sufficient.

### `P-05`, `P-06`, `P-07` — Action Probe Duplication (`5.25 ms`), Synchronous `os.fsync` (`4.53 ms`), and Serial CSS `:hover` (`25.2 ms`)

Prioritize fixing CSS `:hover` N+1 on dense stylesheet sites and disabling unnecessary `fsync` on temp MCP session files; skip complex `verify_fresh`/`perform` API surgery unless scripting high-rate local actions.

    - *Expected Gain:* `0%` wrong-window pixel leakage onto blind crops (`100%` target fidelity on occluded background windows `[INFERRED]`). *Cost/Risk:* ~25 LOC Win32 ctypes; `PrintWindow` may render slower (~`15–40 ms` vs `ImageGrab`) or blank on anti-cheat DRM/exclusive DirectX, so validate non-uniform variance before skipping `ImageGrab`.
  - **Cheaper Alternative:** Whenever `hwnd is not None and GetForegroundWindow() != hwnd`, call `_capture_hwnd_printwindow(hwnd, box)` directly (3-line check, skips Z-order traversal!).
  - **Graceful Fallback:** Emit `kind="window_occluded_or_cloaked"` without attaching deceptive cross-app screenshots when `DWMWA_CLOAKED != 0`.
  - **Pre-Set Test Plan:** Place Window B (`Chrome`) overlapping Window A (`Notepad`/`Paint`) on `Default` desktop -> `capture_desktop_region(A_box, hwnd=A)` returns pixels matching `A`'s UI, never `B`'s pixels; cloaked UWP `SystemSettings.exe` emits warning/zero-leak.
  - **Q/A/S:** **Quality:** Major Gain | **Accuracy:** Major Gain (Eliminates deceptive wrong-app crops `[REPORTED]`) | **Speed:** Neutral/Minor Loss (`~15 ms` only when fallback triggers).
  - **Over-Engineering Check:** Checking `GetForegroundWindow() != hwnd` + `DWMWA_CLOAKED != 0` is ~10 lines and completely prevents the observed bug without DXGI Desktop Duplication complexity.

## M6 — Prioritization & Synthesis

End-to-end agent bottlenecks are dominated by **task success accuracy (OOPIF, `searchbox`, occlusion/UWP crops, Notepad/Explorer UIA reliability)** and **LLM turn count/tokens (`~2–10 s` per LLM step `[REPORTED]`)** — *not* sub-`10 ms` micro-optimizations (`perform` duplicate probe or `os.fsync`).

### 1. What to Fix First (Ranked by End-to-End Agent Impact)
1. **Fix `P-01` ($O(N^2)$ Python Occlusion Filter):** Filter `is_occluded_in_snap()` *only* on interactive candidate nodes (instead of all `5,057` DOM nodes) and viewport-clipped `lay_items`. Turns `300–2,689 ms` Python CPU stalls into `< 5 ms` with zero accuracy risk.
2. **Fix `P-02` & `P-03` & `P-04` (Browser Discovery Recall & Precision):**
   - Add `"searchbox"` to `ROLES` / `INTERACTIVE` / `read_value()` (`P-03`, ~5 LOC — immediate fix for Wikipedia/Python/doc search bars).
   - Add `DOMSnapshot` multi-document tag fallback (`docs[1..]`) or flattened `Target.setAutoAttach` OOPIF `AXTree` (`P-02`) so OOPIF buttons & inputs don't fail silently.
   - Deduplicate `div[onclick]` child `#text` (`clickable` ancestors) and `<label for>` proxies (`P-04`).
3. **Fix `P-10` (Test Reliability, Child Process Leaks & File Mutation):** Match `title_contains=tmp.stem`, terminate `hwnd` owning PID on teardown (or use isolated native Win32 test window), fix `8` pytest return warnings, and remove automatic overwrite of `results/e2e/e2e_results.json`.
4. **Fix `P-09` & `P-08` (Desktop `PrintWindow` Ordering & File Explorer Active Tab Scope):** Check `DWMWA_CLOAKED` + `GetForegroundWindow() != hwnd` before `ImageGrab` so background desktop crops never capture covering IDEs; filter File Explorer hidden DirectUI tab trees cleanly.
5. **Fix `P-19` & `P-11` (Security Defaults & Cross-Platform Guards):** Block private/link-local/loopback SSRF in `validate_navigation_url()` unless explicitly allowed, redact/hash all `TaskState` values in persistence, and guard `WinDLL` imports behind `sys.platform == "win32"`.
6. **Doc & Report Cleanup (`P-22`):** Reconcile `ARCHITECTURE_DECISION.md`, `BENCHMARK_REPORT.md`, `benchmarks_real.*`, and `walkthrough.md` *only after* re-measuring on the post-merge codebase.

### 2. What NOT to Build and Why
- **Do NOT build `H2 Grid 2B` or `H3` visual hover diffing:** Fails Gate 2A empirically (`60%` dead FPs at `30 ms`, `0%` hand signal on Notepad, `25 s` grid scan) and is superseded by `blind_gap` image crops (`click_at`).
- **Do NOT replace UIA discovery with `CoreAutomationRemoteOperation` (`Exp 5`):** Cross-HWND/process walls yield `1.8%–2.9%` subtree recall on Notepad/Chromium.
- **Do NOT replace `DOMSnapshot`+`AXTree` with the `One-Call JS Extractor` (`Exp 6`):** Drops closed Shadow DOM, OOPIFs, and loses `50–62%` of controls on real SPAs (`38.1%` GitHub Trending, `64.1%` YouTube).
- **Do NOT build a full `MutationObserver` incremental DOM engine (`Exp 9`):** Misses closed Shadow DOM + OOPIFs (`recall=0.8421`), while optimizing Python occlusion (`P-01`) + parallel CDP reads already yields sub-`50 ms` authoritative discovery on normal pages.
- **Do NOT optimize `Api.execute_action()` micro-probe (`5.25 ms`, `P-05`) in isolation:** Invisible inside LLM agent loops (`0.1–0.2%` of multi-second turns) unless refactoring `DirectCdpClient` for OOPIF multiplexing (`P-02`).

### 3. Claims That Must Be Removed or Re-Measured Before Publishing Anything
1. **Remove / Re-measure `Exp 8` (`9.543 ms` Browser & `2,013.98 ms` Desktop):** Confounded by missing `TaskState` `os.fsync` in candidate arm and stale pre-`AutoSetFocus=0` run; re-run `bench_action_freshness.py` invoking merged `Api` on identical durability settings & full 6-mode Desktop matrix.
2. **Remove `Control CDP = 1.0000` Real-Site Accuracy Claim:** Relabel explicitly as "agreement vs pre-ERR-01 Control CDP" (circular) or create annotated manual ground truth on real pages; re-run `benchmarks/benchmark_real.py` post-Step 5 fixes with `n >= 10` warm runs and `p50`/`p95` variance.
3. **Resolve `ARCHITECTURE_DECISION.md` & `h3_report.md` Contradictions:** Remove `"BLOCKED IN exebox"` lines (`13, 29`) vs `"Gate 0 passed"`, sync §3 table to `benchmarks_real.json`, and strike invalidated `26.7%/73.3%/12.24 s` figures from `h3_report.md`.
4. **Correct `13/15` -> `14/16` in Step 6 `walkthrough.md`** and explicitly disclose `benchmark_mcp_overhead`'s `-0.15 ms` delta as within Windows scheduling jitter (`p95 = 23–32 ms`), not negative IPC cost.
5. **Do Not Publish `1229`-Token Screenshot Savings Without Live VLM Runs:** `harness_validation.json` had `0` LLM calls; either keep it labeled strictly as an oracle harness validation or execute the real VLM runs (`bench_agent_20tasks.py`) reporting exact API `prompt_tokens` + `completion_tokens` across providers.

### 4. Minimum Additional Experiments Needed to Settle Open Questions
1. **Experiment A — Live Paired 20-Task VLM Evaluation (`bench_agent_20tasks.py` on unlocked `WinSta0\Default`):** Execute all 20 tasks (`screenshot_baseline` vs `computer_use_lite` with `1+` vision LLM, e.g. `gpt-4o` or `gemini-2.5-flash`, `n >= 3` seeds) logging real end-to-end wall time, task pass rate, failure reasons, and provider-reported `prompt_tokens`/`completion_tokens` (validates whether text line maps beat raw screenshots in real agent loops).
2. **Experiment B — Post-Merge Freshness & Discovery Sweep (`Exp 6 + Exp 8 + real_sites` re-run):** Re-run with fixed `P-01` (`is_occluded` on candidates only), fixed `P-02`/`P-03`/`P-04`, identical `TaskState` durability in control & candidate (`Exp 8`), and `n=10` warm repeats (`p50`/`p95`/`stddev`) on `corpus_main`, `/large` (`2,500`-cell), and real sites (`benchmarks_real`).
3. **Experiment C — Interactive Desktop UIA Suite + `PrintWindow` Matrix (`WinSta0\Default`):** Verify `DesktopTarget` on `Notepad` (`AutoSetFocus=0`), `File Explorer` (multi-tab active filtering `P-08`), `Chromium`, `Electron`, and `Settings`/occluded windows (`PrintWindow` pixel match vs `ImageGrab` `P-09`) over `n=10` iterations.
